**项目名称：LuspSearchCore (极速本地文件搜索与监控引擎)** | *独立商业级项目*
**核心技术：C++20 / NTFS MFT 直读 / 倒排索引 / USN 增量监控 / IPC 通信**
[私有闭源 / 具备商业级源码授权能力]

- **文件系统深度规避与底层穿透**：针对 Windows 平台独立实现针对 NTFS 文件系统的 **$MFT（主文件表）直读解析引擎**。全面绕过传统 Win32 API 遍历带来的巨大磁盘 I/O 阻塞。依靠多卷并行扫描与零拷贝内存映射（mmap）技术，达成千万级文件的“数分钟级”全盘冷启动构建。
- **高性能索引算法与查询加速**：自研基于文件名的**三元组（Trigram）倒排索引**架构，辅以多级内存缓存与增量写入层。针对极耗 CPU 资源的模糊匹配与正则表达式查询能够做到极速收敛，千万级数据底座下的复杂检索响应压降至毫无体感的**毫秒级**。
- **实时内核级变更监听（USN Journal）**：挂载利用 NTFS 底层的 **USN（Update Sequence Number）**变更日志机制，实现对多卷文件增删改事件的无级捕捉。结合自适应多核线程池（I/O 与解析任务解耦调度）实现增量数据的秒级热更新与持久化入库，保障空载期间系统资源占用极低（后台静默运行防御性好）。
- **分布式 IPC 架构与前后端隔离**：系统解耦为 `LuspService`（独立搜索内核服务端）和 `LuspClient/LuspGUI`（轻量级客户端交互界面），双方通过高性能进程间通信（IPC）机制全天候交互。彻底将密集的硬盘 I/O 及解析操作与前端 UI 剥离。

3. **IPC（进程间通信）调优与后端驻留**：掌握 Client-Server 本地进程分离架构设计。UI 只负责视图与轻量网络传值，庞大的数据驻留在后台 Service 中。隔离业务状态，防范前端渲染污染到后端的数据索引循环。
