**项目名称：MyTFS (海量小文件分布式存储引擎)** | *个人开源项目*
**核心技术：C++11 / `mmap` 内存映射 / 自定义哈希索引 / 空间碎片整理 / Linux 底层存储 API**
[GitHub 主页](https://github.com/hesphoros/MyTFS/)

- **系统底层架构设计**：基于 **C++** 独立研发对标淘宝海量文件系统（TFS）的存储引擎核心单元。通过将海量零散小文件（如图片、头像数据）聚合物理存储至几十 MB/GB 级的大尺寸 Block 块中，彻底根除传统文件系统（如 Ext4/XFS）下 inode 句柄耗尽及高密度磁盘寻址带来的性能雪崩问题。
- **极致的元数据索引策略**：舍弃传统内存字典，从 0 研发将索引文件（IndexHeader + MetaInfo）完整持久化的内存组织体系。借助 **`mmap` 内存映射零拷贝** 技术把索引结构一次性投射至内存，内置自研的块内偏移量链式哈希桶索引机制，实现海量对象 $O(1)$ 时间复杂度的微秒级寻址。
- **动态碎片重构与空间治理**：为应对对象更新与删除造成的存储空洞，自主开发“空间回收引擎（Space Reclamation / Compaction）”。实时追踪 `del_file_count` 与碎片率状态触发重构机制，将底层数据进行平滑挪移与合并压缩重建，长期维持微服务系统低碎片率及 I/O 吞吐稳定性。
- **严苛的文件 IO 管控**：针对大尺寸文件封装系统调用链路，直接利用 `pread` 与 `pwrite` 规避并发读写时的文件指针竞争（Race Condition）。配合宏命令如 `O_LARGEFILE` 以及自定义多参数块映射模式，保障百 G 级别文件的指针读写越界拦截和系统资源的高效利用。

### 💡 面试高优考点提取 (Interview Highlights)

#### 🛠️ 核心技术点 (Hard Skills)
1. **Linux 系统编程深度掌控**：熟练运用 Linux 核心系统 API 进行高级 IO 编程，如 `ftruncate`, `mmap`, `pread`/`pwrite`，规避 C++ 原生流库在存储引擎中的额外开销风险。
2. **零拷贝（Zero-Copy）实践落地**：使用 `mmap` 打通内核页缓存与用户空间的屏障，大幅降低上下文切换成本以处理密集的索引查询。
3. **定制化数据结构与内存布局**：不在普通对空间分配对象，而是运用原始偏移量在连续映射内存内自造“链表哈希碰撞树”，要求必须极致压缩对象体积（`MetaInfo` 内存布局）并保障断电落盘时指针引用仍然能相互锁定。
4. **底层并发处理前瞻性**：在 `pread`/`pwrite` 原子访问及数据版本控制 `version_` 中的实现，有效证明了多线程底层安全保障的方法论能力。

#### 💎 高价值点 (Business & Architectural Value / "所以呢？")
1. **深谙底层基础设施的“痛点”**：大厂做大规模对象存储 / CDN / 多媒体中台遇到最大的痛就是“文件碎片与 Metadata 元数据瓶颈”。您对抛弃 OS 宿主文件系统自带的 inode 机制了如指掌说明你不仅仅是一名高层程序员，而是一名**懂系统瓶颈在哪里的底层极客**。
2. **造轮底蕴与泛型基础**：这类将结构体强写进磁盘再利用指针 Offset 检索的引擎能力，与自写 MySQL InnoDB 页表、或者自写 Redis LSM/Bitcask 引擎本质上是一致的。**极度对口数据库内核组、分布式存储架构中心或高性能中间件部门。**
3. **架构的动态演进力（Compaction 机制）**：很多应聘者只懂得如何增删改，却不懂得长年累月的碎片怎么“平滑重组清扫（Space Reclamation）”。通过这一机制你能证明你不仅追求“写出来”，还考虑到生产中“几年后的演进、稳定期灾难”，具备成熟的后端防御意识。
