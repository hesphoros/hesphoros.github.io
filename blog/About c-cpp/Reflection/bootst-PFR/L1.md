# 0. 我们最终要解释的东西

你看到的是：

```cpp
boost::pfr::detail::fields_count<T>()
```

我们的目标是理解：

```cpp
struct Person
{
    int age;
    float height;
    double score;
};
```

为什么：

```cpp
constexpr auto n =
    boost::pfr::detail::fields_count<Person>();
```

能够得到：

```cpp
3
```

关键是：

> **C++23 根本没有 API 可以问编译器：“这个 struct 有几个成员？”**

所以 PFR 必须想办法把这个问题转换成编译器已经会回答的问题。

最终它转换成：

```cpp
Person{X, X, X}
```

**能不能进行 aggregate initialization？**

# 2. 第一层：`ubiq_lref_constructor`

先看这个：

```cpp
struct ubiq_lref_constructor
{
    std::size_t ignore;

    template <class Type>
    constexpr operator Type&() const && noexcept
    {
        return detail::unsafe_declval<Type&>();
    }

    template <class Type>
    constexpr operator Type&() const & noexcept
    {
        return detail::unsafe_declval<Type&>();
    }
};
```

这是整个技巧非常关键的一步。

你先不要管：

```cpp
unsafe_declval
```

也不要管：

```cpp
const &&
const &
```

先理解这一句话：

> **`ubiq_lref_constructor` 可以隐式转换成“任意类型的左值引用”。**

比如理论上：

```cpp
ubiq_lref_constructor x;

int& a = x;
float& b = x;
std::string& c = x;
```

因为它拥有：

```cpp
template<class Type>
operator Type&()
```

所以：

```cpp
x
```

可以伪装成：

```cpp
int&
float&
std::string&
Anything&
```

# 3. 为什么需要这个东西？

假设：

```cpp
struct Person
{
    int age;
    float height;
    std::string name;
};
```

我们不知道：

```text
age    是 int
height 是 float
name   是 string
```

但我们可以制造：

```cpp
ubiq_lref_constructor x;
```

然后尝试：

```cpp
Person{
    x,
    x,
    x
};
```

由于：

```cpp
x
```

可以转换成任意字段需要的引用类型。

所以：

```cpp
Person{
    x,
    x,
    x
}
```

如果能够编译：

> Person 至少可以用 3 个初始化参数进行 aggregate initialization。

---

# 4. 这就是整个技巧的核心

你可以先自己写一个极简版本：

```cpp
struct ubiq
{
    template<typename T>
    constexpr operator T&() const;
};
```

然后：

```cpp
struct Person
{
    int age;
    float height;
    double score;
};
```

测试：

```cpp
Person p{
    ubiq{},
    ubiq{},
    ubiq{}
};
```

它能够通过。

但是：

```cpp
Person p{
    ubiq{},
    ubiq{},
    ubiq{},
    ubiq{}
};
```

会失败。

为什么？

因为：

```text
Person 有 3 个成员
```

而 aggregate initialization 给了：

```text
4 个 initializer
```

于是：

```cpp
Person{X, X, X}
```

就是一个非常好的“探针”。

# 5. 第二层：`enable_if_constructible_helper`

PFR 接下来把刚才的实验包装成：

```cpp
template <
    class T,
    std::size_t... I
>
constexpr auto enable_if_constructible_helper(
    std::index_sequence<I...>
)
    -> typename std::add_pointer<
        decltype(
            T{
                ubiq_lref_constructor{I}...
            }
        )
    >::type;
```

这个东西第一次看会非常恶心。

我们把它拆掉。

```cpp
std::index_sequence<I...>
```

```cpp
std::make_index_sequence<3>()
```

得到：

# 6. 现在关键来了

如果：

```cpp
T = Person
```

那么：


内部相当于尝试：


能成功：

那么这个函数模板的返回类型有效。


```text

```

于是这个模板发生 SFINAE。

# 7. 这就是 PFR 的“探针”

可以把它理解成：

```text
                    T
                    │
                    ▼
       ┌──────────────────────┐
       │ 能不能写 T{X, X, ...} │
       └──────────┬───────────┘
                  │
           ┌──────┴──────┐
           │             │
          YES            NO
           │             │
           ▼             ▼
       至少 N 个       少于 N 个
```

注意这里非常重要：

> 它不是直接读取成员数量。

而是：

> **通过合法/非法的 C++ 语法反推出成员数量。**

这就是模板元编程里非常经典的 **probe / detection** 思维。

# 8. 第三层：为什么叫 `fields_count`

现在我们可以定义一个最简版本：

```cpp
template<typename T, std::size_t N>
concept can_construct =
    requires
    {
        T{
            /* N 个 ubiq */
        };
    };
```

然后：

```text
N = 0
N = 1
N = 2
N = 3
N = 4
...
```

不停尝试。

对于：

```cpp
struct Person
{
    int age;
    float height;
    double score;
};
```

结果：

```text
Person{}
             ✔

Person{X}
             ✔

Person{X,X}
             ✔

Person{X,X,X}
             ✔

Person{X,X,X,X}
             ✘
```

于是：

```text
最大成功 N = 3
```

所以：

```cpp
fields_count<Person>() == 3
```

# 10. PFR 的聪明之处：二分搜索

源码里有：

```cpp
detect_fields_count<T, Begin, Middle>
```

以及：

```cpp
multi_element_range
```

它会尽量做：

```text
                    0 ~ 100
                       │
                       ▼
                      50
                    /    \
                  /        \
              0~50          50~100
                │                │
                ▼                ▼
               25               75
```

也就是：

> **通过 aggregate initialization 的结果进行二分搜索。**

因此理论上搜索深度大约：

```text
O(log N)
```

这对模板编译性能非常重要。

源码注释也明确说明了它在这里使用不同搜索策略，并讨论了模板实例化深度/数量。([Boost](https://beta.boost.org/doc/libs/1_82_0/boost/pfr/detail/fields_count.hpp?utm_source=chatgpt.com "boost/pfr/detail/fields_count.hpp - 1.82.0"))

# 11. 但是为什么源码还有 `greedy`？

这是一个很重要的坑。

假设：

```cpp
struct X
{
    NonDefaultConstructible a;
    int b;
};
```

你不能简单假设：

```cpp
X{}
```

一定成立。

因此：

```cpp
T{X, X, X}
```

的可构造性和字段数量之间会出现一些特殊情况。

所以 PFR 有：

```cpp
detect_fields_count_greedy
```

作为 fallback。

源码对此明确写了：

> 如果 T 不是 default aggregate initializable，就不能使用普通二分搜索，需要检查直到 N 的 aggregate initialization，并取最大的成功值。([代码浏览器](https://codebrowser.dev/boost/boost/libs/pfr/include/boost/pfr/detail/fields_count.hpp.html?utm_source=chatgpt.com "fields_count.hpp source code [boost/libs/pfr/include/boost/pfr/detail/fields_count.hpp] - Codebrowser"))

所以你读源码时不要看到：

```cpp
binary search
```

就以为 PFR 永远二分。

它其实是：

```text
                    fields_count
                         │
                         ▼
                  dispatch strategy
                   /             \
                  /               \
          binary search          greedy
```

# 12. 第四层：`detect_fields_count_dispatch`

这是一个非常值得你仔细看的函数。

大概结构：

```cpp
template <class T, std::size_t N>
constexpr auto detect_fields_count_dispatch(...)
```

它会根据类型情况选择不同策略。

源码中目前有几个重要分支：

### 数组

```cpp
std::is_array<T>::value
```

直接：

```cpp
sizeof(T) / sizeof(element)
```

### 可以默认构造

尝试：

```cpp
sizeof(T{})
```

然后进入：

```cpp
detect_fields_count<T, ...>
```

也就是：

```text
二分搜索
```

---

### 不能默认构造

进入：

```cpp
detect_fields_count_greedy<T, 0, N>
```

也就是：

```text

```

源码可以直接看到这三个 dispatch 分支。([代码浏览器](https://codebrowser.dev/boost/boost/libs/pfr/include/boost/pfr/detail/fields_count.hpp.html?utm_source=chatgpt.com "fields_count.hpp source code [boost/libs/pfr/include/boost/pfr/detail/fields_count.hpp] - Codebrowser"))

# 13. 最终回到 `fields_count<T>()`

现在我们终于可以看懂：

```cpp
template <class T>
constexpr std::size_t fields_count() noexcept
{
    using type = std::remove_cv_t<T>;

    ...

    constexpr std::size_t max_fields_count =
        sizeof(type) * CHAR_BIT;

    constexpr std::size_t result =
        detail::detect_fields_count_dispatch<type>(
            size_t_<max_fields_count>{},
            1L,
            1L
        );

    ...

    return result;
}
```

这里最重要的一句：

```cpp
constexpr std::size_t result =
    detail::detect_fields_count_dispatch<type>(...);
```

整个流程终于串起来：

```text
fields_count<Person>()
        │
        ▼
detect_fields_count_dispatch<Person>()
        │
        ▼
选择搜索策略
        │
        ▼
尝试：
Person{X}
Person{X,X}
Person{X,X,X}
Person{X,X,X,X}
        │
        ▼
得到最大成功 N
        │
        ▼
result = 3
        │
        ▼
return 3
```

# 14. `max_fields_count` 为什么是 `sizeof(T) * CHAR_BIT`？

这个地方也很有意思。

源码：

```cpp
constexpr std::size_t max_fields_count =
    sizeof(type) * CHAR_BIT;
```

比如：

```cpp
struct Person
{
    int age;
    float height;
    double score;
};
```

假设：

```text
sizeof(Person) = 16
CHAR_BIT = 8
```

那么：

```text
max_fields_count = 128
```

为什么？

因为 C++ 有：

```cpp
bit-field
```

例如：

```cpp
struct X
{
    unsigned a : 1;
    unsigned b : 1;
    unsigned c : 1;
    ...
};
```

一个字节里理论上可以塞很多 bit-fields。

所以不能简单：

```cpp
max = sizeof(T)
```

源码明确采用 `sizeof(type) * CHAR_BIT`，并且在旧实现/不同 copy-elision 能力下还有不同限制。([Boost](https://beta.boost.org/doc/libs/1_82_0/boost/pfr/detail/fields_count.hpp?utm_source=chatgpt.com "boost/pfr/detail/fields_count.hpp - 1.82.0"))

# 17. 但是这里有一个非常重要的细节

你可能会想到：

```cpp
T{
    ubiq{},
    ubiq{},
    ubiq{}
}
```

为什么可以判断：

```text
3 个成员？
```

对于：

```cpp
struct A
{
    int a;
    int b;
    int c;
};
```

很好理解。

但是：

```cpp
struct A
{
    int a;
    int b;
};
```

`A{X, X, X}` 不允许。

**但 C++ aggregate initialization 本身允许 trailing members 使用默认成员初始化器。**

例如：

```cpp
struct A
{
    int a;
    int b = 42;
};
```

那么：

```cpp
A{X}
```

也合法。

所以：

```text
能用 N 个参数初始化
```

并不简单等于：

```text
有 N 个字段
```

这也是为什么真正的 PFR 实现有很多细节。
