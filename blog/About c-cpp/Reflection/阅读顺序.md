# 第一目标：搞懂“它怎么知道一个 struct 有几个字段”

这是最值得你研究的地方。

例如：

```cpp
struct User
{
    int id;
    float score;
    std::string name;
};
```

PFR 要回答：

```cpp
field_count<User>()
```

为什么是：

```text
3
```

C++23 并没有：

```cpp
std::reflection::field_count<T>()
```

所以它必须“骗”编译器。

核心思路和：

```cpp
T{anything, anything, anything}
```

的 aggregate initialization 有关。

你读代码的时候一直追：

```text
field_count
    ↓
is_initializable
    ↓
aggregate initialization
    ↓
N 个参数
    ↓
确定字段数量
```

**这个过程建议你自己画一遍。**

---

# 第二目标：搞懂 `tie_from_structure`

这是第二个重点。

最终 PFR 要做到：

```cpp
User user;

auto tuple =
    boost::pfr::structure_to_tuple(user);
```

得到：

```text
tuple
 ├── user.id
 ├── user.score
 └── user.name
```

然后：

```cpp
std::get<0>(tuple)
```

实际上访问：

```cpp
user.id
```

所以你要搞清楚：

> **它到底是如何把一个 struct 拆成 structured bindings 的。**

这是你以后自己实现：

```cpp
meta::fields<T>()
```

的基础。

# 第三目标：理解 `for_each_field`

当你已经知道：

```text
User
 ↓
field_count = 3
 ↓
field tuple
```

再看：

```cpp
boost::pfr::for_each_field(
    user,
    [](auto& field)
    {
        ...
    }
);
```

它实际上就是：

```text
User
 ↓
field tuple
 ↓
tuple iteration
 ↓
compile-time index
 ↓
lambda
```

这部分应该比较容易。

# 然后才看 Boost.MP11

PFR 看懂之后，再进入：

> **“如何组织这些 Meta Information？”**

这就是 MP11。

重点不是读 MP11 所有代码。

你只需要理解：

```cpp
mp_list
mp_transform
mp_for_each
mp_at_c
mp_size
mp_contains
mp_filter
```

例如最终你可能设计：

```cpp
using Members = hes::meta::members<User>;
```

得到：

```cpp
mp_list<
    Member<0, int>,
    Member<1, float>,
    Member<2, std::string>
>
```

然后：

```cpp
mp_for_each<Members>([](auto member)
{
});
```

这就是你的：

```text
Compile-time Meta Graph
```

# 第三站：refl-cpp

这时候再读 refl-cpp，你会突然容易很多。

因为你已经知道：

```text
字段怎么发现
       ↓
字段怎么变成 compile-time entity
       ↓
tuple / type list 怎么遍历
```

这时候看 refl-cpp：

```text
reflect<T>()
    ↓
member
    ↓
property
    ↓
method
    ↓
enum
    ↓
metadata
```

重点研究：

### 1. Reflection API

```cpp
refl::reflect<T>()
```

### 2. Member

```cpp
refl::member_pointer
```

### 3. Compile-time iteration

```cpp
refl::util::for_each
```

### 4. Metadata

```cpp
refl::attr
```

### 5. Type information

```cpp
refl::type
```

你会发现它其实已经很接近：

```text
HesMeta
```

# 然后才轮到 RTTR

这时候再看 RTTR，你的目的已经不是：

> “RTTR 怎么实现？”

而是：

> **“一个完整 Reflection Framework 应该提供什么 API？”**

重点看：

```text
rttr::type
rttr::property
rttr::method
rttr::enumeration
rttr::variant
rttr::instance
rttr::registration
```

你可以把它整理成：

```text
Type
├── Properties
├── Methods
├── Constructors
├── Enums
├── Metadata
└── Base Classes
```

然后问自己：

> 哪些东西应该留在 compile-time？

例如：

```text
TypeInfo<T>                 constexpr
PropertyInfo<T, I>          constexpr
FieldType<T, I>             constexpr
FieldName<T, I>             constexpr
Getter<T, I>                constexpr
Setter<T, I>                constexpr
```

而不是 RTTR 那种：

```text
Type
 ↓
Runtime Registry
 ↓
Runtime lookup
```

# Qt MetaObject 放最后

你本身就在做 HesWidgets，所以 Qt 很值得看。

但现在不要研究：

```text
moc 是怎么生成 cpp 的
```

而是研究：

```text
QMetaObject
QMetaProperty
QMetaMethod
QMetaEnum
```

重点理解：

> **Qt 是怎么把“类型 → 属性 → 方法 → 信号”组织起来的。**

你会发现：

```text
RTTR
Qt
Unreal
```

虽然实现完全不同，但是：

```text
Type
Property
Method
Enum
Metadata
Inheritance
```

这些概念高度一致。

这就是你自己的 Meta Model 应该吸收的东西。
