
###  C 语言的类型擦除

C 语言没有模板和运行时多态，只能通过**“万能指针 + 函数指针”**手动擦除类型。

- **核心模式**：`void*` 擦除数据类型，函数指针擦除行为类型。
- **典型场景**：`qsort` 比较函数、线程回调、事件注册。

```c
// 擦除后的统一类型：返回 void，接受 void* 
typedef void (*ErasedCallback)(void* user_data);

typedef struct {
    ErasedCallback cb;
    void* data;          // 擦除了具体数据类型的指针
} CallbackHandle;

// 使用时，用户强转回原类型
void timer_handler(void* arg) {
    MyData* d = (MyData*)arg; // 手动恢复类型
    // ...
}
```

**缺点**：类型不安全（全靠人为约定），且不管理内存生命周期（谁分配谁释放）。

### 2. C++ 的类型擦除（标准库方案）

C++ 提供了更优雅、安全的解决方案，最典型的就是 **`std::function`**（C++11）。

```cpp
#include <functional>
#include <iostream>

int add(int a, int b) { return a + b; }

int main() {
    // 同一类型 std::function<int(int,int)> 擦除了底层具体类型
    std::function<int(int,int)> f1 = add;           // 函数指针
    std::function<int(int,int)> f2 = [](int a, int b) { return a * b; }; // Lambda
    std::function<int(int,int)> f3 = std::plus<int>(); // 仿函数对象
    
    // 统一调用
    std::cout << f1(1,2) << f2(2,3) << f3(4,5); 
    return 0;
}
```

### 3. C++ 类型擦除的底层原理（核心机制）

如果你在面试或源码阅读中遇到，必须理解其背后的 **“外部多态（External Polymorphism）”** 模式。`std::function` 的实现本质是**“模板生成具体子类 + 虚函数调度”**。

**简化的手写实现**：

```cpp
template <typename Signature>
class MyFunction;

// 偏特化：仅针对 int(int) 这类签名
template <typename Ret, typename... Args>
class MyFunction<Ret(Args...)> {
private:
    // 1. 定义抽象基类（概念接口），擦除具体类型
    struct Concept {
        virtual ~Concept() = default;
        virtual Ret invoke(Args... args) = 0;
        virtual Concept* clone() const = 0; // 支持拷贝
    };

    // 2. 模板派生类（具体模型），持有具体对象的实例
    template <typename Callable>
    struct Model : public Concept {
        Callable m_callable;
        Model(Callable c) : m_callable(std::move(c)) {}
        Ret invoke(Args... args) override {
            return m_callable(std::forward<Args>(args)...);
        }
        Concept* clone() const override {
            return new Model<Callable>(m_callable);
        }
    };

    Concept* m_concept = nullptr;

public:
    // 构造函数：接收任意可调用对象，生成对应的 Model 实例
    template <typename Callable>
    MyFunction(Callable c) 
        : m_concept(new Model<Callable>(std::move(c))) {}

    // 拷贝构造（深拷贝，或使用小对象优化 SBO）
    MyFunction(const MyFunction& other) {
        if (other.m_concept) m_concept = other.m_concept->clone();
    }

    // 函数调用操作符
    Ret operator()(Args... args) const {
        return m_concept->invoke(std::forward<Args>(args)...);
    }

    ~MyFunction() { delete m_concept; }
};
```

**关键逻辑解读**：

1.  **`Concept`（基类）**：定义虚函数 `invoke`，这是对外暴露的统一接口，**擦除了具体实现类型**。
2.  **`Model<T>`（派生类模板）**：模板参数 `T` 记录了用户传入的真实类型（如 Lambda 的匿名类）。`Model` 实例化时生成了与该类型绑定的 `invoke` 实现。
3.  **构造函数模板**：接受任意类型，`new Model<T>(c)` 构建派生类对象，赋值给基类指针 `m_concept`。从此，外部的 `MyFunction` 只知道基类指针，**具体类型 T 被彻底擦除**。

### 4. 性能与内存（小对象优化 SBO）

为了优化堆分配开销，标准库实现通常带有 **SBO（Small Buffer Optimization）**。

- 如果 `Callable` 对象很小（例如 Lambda 只有 1~2 个字节），它会被直接存放在 `MyFunction` 对象的栈空间缓冲区中，避免 `new` 堆分配。
- 如果 `Callable` 很大（如捕获了大量变量的 Lambda），则回退到堆分配。

这也是为什么 `std::function` 有固定大小（通常为 32 或 48 字节）——它内部预埋了一段原始字节数组用于就地存储。

### 5. C++23 及现代的变种演进

了解它们能体现你对现代 C++ 的认知广度：

- **`std::move_only_function` (C++23)**：支持移动语义但不支持拷贝，避免不必要的深拷贝开销，适合只移动的对象。
- **`std::function_ref` (C++26 / TS)**：**非持有型（Non-owning）**，相当于一个“万能函数引用”。它只保存对象的指针和虚表指针，不管理生命周期，性能极高（零堆分配、零拷贝），适合用作函数参数传递，但调用者必须保证对象在调用期间存活。

### 总结：何时使用？

| 方案 | 适用场景 | 开销 |
| :--- | :--- | :--- |
| **模板（编译时多态）** | 编译期确定类型，追求极致性能（如排序、算法库）。 | 零运行时开销，代码膨胀。 |
| **`std::function`（类型擦除）** | 需要**运行时**存储、回调、事件分发，类型不确定。 | 虚函数调用开销 + 可能的堆分配。 |
| **`auto` + `concepts`（C++20）** | 编译期泛型，但不想写繁琐模板语法。 | 零运行时开销。 |
| **`std::function_ref`（C++26）** | 运行时传递回调，且生命周期由调用者保证（如 `std::for_each`）。 | 极低（仅指针解引用），不堆分配。 |
